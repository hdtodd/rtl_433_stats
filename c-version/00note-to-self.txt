2026.06.19

Branch 2.3.1 is a development branch off 2.3
In developing the c code for 2.3, I found that the Python code was incorrectly categorizing
some packets as duplicates.  Note those with "1185M" in xaa.json, in particular: there are
4 distinct packets; the c code recognized them as distinct transmissions; the Python code
thought there were 4 packets but that 1 was a dup.  I'm guessing that the Python code used
the time for the PRIOR PACKET RECEIVED, not the timestamp for the PRIOR PACKET FOR THAT DEVICE
to decide if it was a dup or not.  Total number of "dups" in Python code for that test set
was about 100 more than for the c code.  In a high-volume area, that count would be far worse.

Corrected the Python code and it now gets the xmit count correctly.

I also want to revise the output to order cols as SNR, Freq, ITGT, PKT and eliminate
redundant xmit cols.
